Installazione guidata

Segui un passaggio alla volta. Alla fine avrai un indirizzo da dare ai giocatori, con gli stessi strumenti della campagna e provviste basate solo sulle razioni.

0 di 7 passaggi completati

1. Prima di cominciare

Estrai tutto lo ZIP: su Windows fai clic destro → Estrai tutto; su Mac fai doppio clic. Apri questo file INIZIA-QUI.html dalla cartella estratta.

Per la prima installazione usa un computer. Ti serviranno tre account amministrativi, solo per te:

ServizioA cosa serve
GitHubConserva una copia privata del codice del sito.
SupabaseConserva appunti, account e immagini.
NetlifyRende il sito accessibile su Internet.

I giocatori useranno solo il loro nome e la chiave della campagna. Il tuo computer potrà rimanere spento mentre giocano.

Quanto costa?

Puoi iniziare con i piani Free. Hanno limiti: Netlify include 300 crediti mensili; Supabase include 500 MB per il database e 1 GB per le immagini e mette in pausa i progetti gratuiti dopo una settimana di inattività. Controlla il pannello prima di una sessione dopo una pausa.

Le condizioni possono cambiare: verifica i piani Netlify e i piani Supabase prima di scegliere. Un dominio acquistato da te è facoltativo.

Il pacchetto include codice, mappa e account iniziali. Gli appunti e le immagini caricati sul sito attuale vanno trasferiti al passo 4. Il nuovo sito non è ancora pubblicato.

2. Crea lo spazio per i dati

  1. Apri Supabase. Crea un’organizzazione Free, se richiesta, poi premi New project.
  2. Chiama il progetto Barovia. Scegli una regione europea se giocate dall’Italia. Genera una password del database e conservala: ti servirà al prossimo passo. Premi Create new project e attendi che sia pronto.
  3. Apri SQL Editor nel menu del progetto e crea una nuova query. Premi il pulsante qui sotto, incolla tutto nell’editor e premi Run.
Mostra il testo da copiare
-- Run once in the SQL Editor of a dedicated Supabase project.
-- This private schema must NOT be added to the exposed Data API schemas.
BEGIN;
CREATE SCHEMA IF NOT EXISTS barovia;
REVOKE ALL ON SCHEMA barovia FROM PUBLIC, anon, authenticated;
CREATE TABLE IF NOT EXISTS barovia.users (
 id text PRIMARY KEY, name text NOT NULL UNIQUE, role text NOT NULL CHECK (role IN ('dm','player')),
 hash text NOT NULL, salt text NOT NULL, active integer NOT NULL DEFAULT 1 CHECK(active IN (0,1)), changed integer NOT NULL DEFAULT 0
);
CREATE UNIQUE INDEX IF NOT EXISTS users_name_lower ON barovia.users(lower(name));
CREATE TABLE IF NOT EXISTS barovia.sessions (
 token text PRIMARY KEY, user_id text NOT NULL REFERENCES barovia.users(id), expires bigint NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_sessions_user ON barovia.sessions(user_id);
CREATE INDEX IF NOT EXISTS idx_sessions_expires ON barovia.sessions(expires);
CREATE TABLE IF NOT EXISTS barovia.attempts (key text PRIMARY KEY, count integer NOT NULL, reset bigint NOT NULL);
CREATE TABLE IF NOT EXISTS barovia.records (
 id text PRIMARY KEY, kind text NOT NULL, title text NOT NULL, body text NOT NULL DEFAULT '',
 owner text NOT NULL REFERENCES barovia.users(id), audience text NOT NULL, folder text NOT NULL DEFAULT '',
 data text NOT NULL DEFAULT '{}', links text NOT NULL DEFAULT '[]', version integer NOT NULL DEFAULT 1,
 updated bigint NOT NULL, editor text NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_records_kind ON barovia.records(kind);
CREATE TABLE IF NOT EXISTS barovia.settings (id text PRIMARY KEY, value text NOT NULL, version integer NOT NULL DEFAULT 1);
CREATE TABLE IF NOT EXISTS barovia.uploads (id text PRIMARY KEY, owner text NOT NULL, mime text NOT NULL, created bigint NOT NULL);
ALTER TABLE barovia.users ENABLE ROW LEVEL SECURITY;
ALTER TABLE barovia.sessions ENABLE ROW LEVEL SECURITY;
ALTER TABLE barovia.attempts ENABLE ROW LEVEL SECURITY;
ALTER TABLE barovia.records ENABLE ROW LEVEL SECURITY;
ALTER TABLE barovia.settings ENABLE ROW LEVEL SECURITY;
ALTER TABLE barovia.uploads ENABLE ROW LEVEL SECURITY;
REVOKE ALL ON ALL TABLES IN SCHEMA barovia FROM PUBLIC, anon, authenticated;
-- No policies grant browser access. The Netlify server enforces campaign ACLs.
INSERT INTO storage.buckets (id,name,public,file_size_limit,allowed_mime_types)
 VALUES ('barovia-media','barovia-media',false,4194304,ARRAY['image/png','image/jpeg','image/webp'])
 ON CONFLICT(id) DO UPDATE SET public=false,file_size_limit=4194304,allowed_mime_types=EXCLUDED.allowed_mime_types;
COMMIT;
  1. Il risultato deve indicare successo, anche se dice che non ci sono righe da mostrare.
  2. Apri Storage: deve esserci barovia-media, indicato come Private.

Hai appena creato le tabelle vuote. Il login e i dati verranno gestiti dal sito. Non occorre creare gli account dei giocatori nel pannello Auth di Supabase.

Compare un errore rosso?

Verifica di avere incollato tutto, dalla riga BEGIN alla riga COMMIT. Usa un progetto Supabase dedicato a Barovia. Se l’errore rimane, conserva il testo dell’errore e il nome di questo passaggio.

3. Prepara i collegamenti

Questi dati permettono al sito di trovare il suo archivio. Questo modulo funziona solo nel tuo browser: non invia i valori su Internet e non li conserva quando chiudi la pagina. Scarica la configurazione prima di chiuderla e tienila privata.

E. Certificato del database, se necessario

Se la connessione segnala un certificato non riconosciuto, in Supabase apri Database Settings → SSL Configuration e scarica il certificato CA. Aprilo con Blocco note/TextEdit e incollalo qui, comprese le righe BEGIN CERTIFICATE ed END CERTIFICATE. Puoi prepararlo anche subito. Mantieni attiva la verifica del certificato.

Riferimenti: connessione al database, chiavi Supabase.

4. Trasferisci gli appunti, se ci sono

Non avete ancora inserito nulla da conservare? Puoi completare questo passaggio e andare avanti. Il primo accesso creerà i sette account con le chiavi iniziali e i luoghi di partenza.

Avete già appunti, immagini o una storia da conservare? Esegui il trasferimento adesso, prima di aprire il nuovo sito: l’importazione richiede un archivio vuoto.

  1. Durante una pausa nelle modifiche, ciascun partecipante apre il sito attuale con il proprio account e sceglie Impostazioni → Il tuo account → Esporta contenuti e immagini.
  2. Crea una cartella chiamata backups nella cartella estratta del sito e mettici i file JSON scaricati. Raccogli anche l’esportazione del DM, necessaria per calendario e impostazioni.
  3. Sposta qui anche .env.netlify.local, preparato al passo 3, accanto a package.json. Mantieni il nome esatto: niente .txt finale.
  4. Installa Node.js, versione LTS 22 o successiva, con le opzioni standard. Serve solo per questo trasferimento.
Se usi Windows

Fai doppio clic su IMPORTA-WINDOWS.cmd, nella cartella del sito. Attendi la preparazione: poi vedrai quanti account, pagine e immagini saranno trasferiti.

Se il riepilogo è corretto e gli archivi ci sono tutti, scrivi IMPORTA e premi Invio. Per accettare esplicitamente archivi mancanti, il programma offre IMPORTA PARZIALE. Attendi “Importazione completata”. Chiudi la finestra soltanto alla fine.

Se usi Mac
  1. Apri Terminale con Spotlight.
  2. Scrivi cd con uno spazio finale, trascina la cartella del sito nella finestra e premi Invio.
  3. Copia ed esegui npm ci. Attendi che finisca.
  4. Copia ed esegui npm run transfer:guided, controlla il riepilogo e scrivi IMPORTA quando richiesto.

L’esportazione del DM non comprende le pagine nascoste al DM. Ogni file contiene solo ciò che l’account può leggere; consegnarlo a chi importa permette a quella persona di leggerne il contenuto. I link, le immagini e la visibilità vengono conservati quando gli archivi necessari sono disponibili.

Le chiavi modificate sul vecchio sito non sono esportate: sul nuovo sito i sette account ripartono dalle chiavi iniziali. Gli account aggiuntivi richiedono una nuova chiave e l’attivazione dal DM.

Il vecchio sito non mostra “Esporta contenuti e immagini” o non è accessibile ai giocatori

Potrebbe mostrare una pubblicazione precedente o avere ancora l’accesso di hosting riservato a te. Non inizializzare il nuovo sito se vuoi trasferire tutto. Occorre prima aggiornare l’esportazione sul vecchio sito o completare l’accesso dei partecipanti; puoi tornare in chat indicando questo passaggio. Le chiavi della campagna non superano il blocco di accesso imposto da Sites.

Il programma dice “Database non vuoto”

Il nuovo sito è già stato aperto oppure il progetto contiene altri dati. L’importazione si ferma per preservarli. Usa un nuovo progetto Supabase dedicato e ripeti dal passo 2; non cancellare tabelle alla cieca.

5. Carica il progetto su GitHub

Qui crei una copia privata del codice. Userai pulsanti e copia/incolla di cartelle.

  1. Installa GitHub Desktop, aprilo ed entra con il tuo account GitHub.
  2. Scegli File → New repository. Nome: barovia-campagna. Ricorda il percorso mostrato in Local path. Premi Create repository.
  3. Scegli Repository → Show in Explorer su Windows o Show in Finder su Mac.
  4. Copia in questa cartella i file e le sottocartelle del sito estratto. package.json e netlify.toml devono comparire direttamente qui, non dentro un’altra sottocartella. Includi .gitignore; su Mac i file nascosti si mostrano con Cmd+Shift+punto, su Windows con Visualizza → Mostra → Elementi nascosti. Tieni backups e .env.netlify.local nella cartella originale sul computer. Se presenti, lascia lì anche node_modules, dist-netlify e .sites-runtime: sono file di lavoro ricreabili.
  5. Torna in GitHub Desktop. Nel campo Summary scrivi “Prima versione di Barovia” e premi Commit to main.
  6. Premi Publish repository. Lascia selezionato Keep this code private e conferma.

Da Repository → View on GitHub puoi controllare che compaiano package.json, netlify.toml e le cartelle del sito. In alto, accanto al nome, deve esserci Private.

Riferimento: pubblicare con GitHub Desktop.

6. Metti il sito online

  1. Apri Netlify. Scegli Add new project → Import an existing project o Import from Git, poi GitHub.
  2. Autorizza l’accesso al solo progetto barovia-campagna e selezionalo. Il ramo da pubblicare è main.
  3. Controlla i valori qui sotto. Dovrebbero essere già letti dal file di configurazione.
CampoValore
Base directoryLascia vuoto
Build commandnpm run build:netlify
Publish directorydist-netlify
Functions directorynetlify/functions (già configurata nel file)
  1. In Add environment variables, aggiungi i valori del passo 3. Puoi usare “Import from a .env file” e incollare il testo ottenuto con “Copia tutte le variabili”. In alternativa aggiungile una alla volta con nome e valore. Usa il contesto Production; se compare la scelta dell’ambito, includi Functions.
  2. Premi Deploy o Deploy project e attendi Published. Il primo avvio può richiedere alcuni minuti.
  3. Se non hai trovato le variabili nella creazione iniziale, apri Project configuration → Environment variables, aggiungile e poi vai in Deploys → Trigger deploy → Deploy site. Anche dopo ogni correzione delle variabili serve una nuova pubblicazione.
  4. Apri il link HTTPS assegnato da Netlify, del tipo nome-scelto.netlify.app. Accedi come DM con la chiave iniziale della campagna.

La chiave amministrativa Supabase va solo nelle variabili di Netlify. Non aggiungere prefissi VITE_ o NEXT_PUBLIC_ ai nomi e non inserirla nel codice. Gli account dei giocatori sono già previsti dal sito.

Vedo il login, ma compare “La campagna non è disponibile”

Controlla i quattro nomi: DATABASE_URL, SUPABASE_URL, SUPABASE_SERVICE_ROLE_KEY, SUPABASE_STORAGE_BUCKET. Il bucket deve essere barovia-media. Verifica di avere eseguito la query SQL e di avere usato il Transaction pooler. Se l’errore riguarda il certificato, aggiungi DATABASE_CA_CERT con il certificato descritto al passo 3. Ripubblica dopo la correzione. Un progetto Supabase in pausa va riattivato dal suo pannello.

La compilazione fallisce o vedo “Page not found”

In Deploys apri la pubblicazione non riuscita e leggi le ultime righe del registro. Controlla che il progetto GitHub non contenga una sottocartella aggiuntiva e che il comando e la cartella pubblicata corrispondano alla tabella. Per chiedere aiuto, copia l’errore e indica “passo 6”, omettendo password e chiavi.

Riferimenti: importazione da Git e variabili delle Functions.

7. Controlla e invita i giocatori

  • Crea una nota di prova con immagine e visibilità riservata. In una finestra privata del browser entra come giocatore escluso e verifica che non compaia.
  • Controlla il calendario, i percorsi della Storia e le razioni. Se hai importato dati, confronta anche qualche vecchio appunto e immagine.
  • Ogni utente può cambiare la propria chiave in Impostazioni. Dopo il trasferimento valgono inizialmente le chiavi originali.
  • Comunica ai giocatori il nuovo link netlify.app. Da quel momento usate quello: vecchio e nuovo sito non si sincronizzano.

Un dominio personale è facoltativo

Puoi giocare con l’indirizzo assegnato. Se hai un dominio, apri Domain management → Add a domain su Netlify e segui i record DNS che ti mostra per il tuo nome. Il venditore del dominio ha il pannello in cui copiarli. Attendi che HTTPS sia attivo; gli utenti dovranno accedere di nuovo sul nuovo indirizzo. Guida domini Netlify.

Backup e aggiornamenti

Dopo le sessioni importanti conserva le esportazioni degli account che devono salvare i propri appunti privati. Per un aggiornamento del codice, sostituisci i file nella stessa cartella GitHub Desktop, esegui Commit e Push origin. Netlify pubblicherà il codice nuovo; i dati resteranno in Supabase.

La guida e il trasferimento non devono rimanere aperti per usare il sito. Conserva il pacchetto originale, gli accessi ai tre servizi e i backup in un posto sicuro.
